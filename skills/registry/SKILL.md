# Evidence registry

Output, all under `.paperloop/`:
- `registry.py` — ONE script that reads raw result files (per-run / per-instance CSV, JSON, JSONL, logs) and recomputes every reportable number. It must contain assertions that fail loudly (expected row counts per condition, seeds per cell, no NaNs, labels matching the code that produced them).
- `registry.json` — what the script writes: `{"numbers": [{"key": "main_gap", "value": 0.183, "n": 200, "ci": [0.12, 0.24], "unit": "proportion", "source": "results/x.csv", "recompute": "python .paperloop/registry.py", "label": "plain description"}]}`.
- `numbers.tex` — `\newcommand{\plnum}[1]{...}`-style macros, one per key (e.g. `\def\plMainGap{0.183}`), generated by the script. In write mode the writer uses these macros for every result number in prose; an undefined macro breaks compilation, so a typo cannot ship.
- `coverage.md` — every results directory and file, marked read / sampled / skipped, with row counts.

## Steps
1. Read `.paperloop/config.json`, `PROJECT-LOG.jsonl` and `DECISIONS.md` if present. List every file under `experiments_dirs`. Mark each read / sampled / skipped in `coverage.md`. A skipped directory that holds the bulk of the results blocks the next stage: say so and stop.
2. Prefer raw files over summaries: result files outrank logs, logs outrank prose reports. Where a project already has a reproduction script (e.g. `reproduce.sh`, an `OUTPUTS` list), call it or read its outputs, and record that.
3. For each condition name you use, find the code that produced it and check the label means what the paper will say it means.
4. Include at least one number whose value is known in advance (a sanity row: a baseline, a ceiling, a count) and assert it.
5. In **revise** mode, also extract every number already in the paper (`paperloop-numbers MAIN_TEX --registry .paperloop/registry.json --json`) and try to trace each unmatched one to a raw file; add it with its source, or list it in `coverage.md` under "numbers in the paper with no source found". Do not change the paper.
6. Run the script twice; the outputs must be identical.
7. Log a `result` event to `PROJECT-LOG.jsonl` (count of numbers, coverage) with refs.

Final message: registry size, how many paper numbers traced (revise mode), anything skipped or not reproducible.
